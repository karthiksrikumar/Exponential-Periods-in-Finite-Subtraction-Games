Results

In the subtraction game with move set S, a heap of n tokens is reduced by some s ∈ S per move, and the player who cannot move loses. The win/loss (P/N) sequence is eventually periodic. Guy conjectured that for |S| = n the period is bounded by a polynomial of degree n(n−1)/2 in max S. Flammenkamp conjectured the opposite from experiments. Whether super-polynomial periods exist at all was open.

Theorem 1: exponential periods

For every k ≥ 2 there is an explicit move set Sk with exactly 26 moves and max Sk = 260k − 16, whose outcome sequence has least period exactly 260 · k · 2k = (max Sk + 16) · 2(max Sk + 16)/260. In particular the period exceeds 2max S / 260, and the nim-sequence period is a multiple of it.

So Guy's conjecture is false and Flammenkamp's conjecture is true. The first k for which the period beats (max S)325 is k = 6719, where max S = 1,746,924.

The setting is the standard game: one heap, finite S, normal play, and the usual recursion from n = 0, with no seed, no modified start and no extra heaps. The number of moves is fixed, and the growth is exponential in the largest move itself, not just in a parameter.

Theorem 2: universality with a bounded number of moves

For every cellular automaton F there is a fixed list of move templates (a, c, δ) such that, for every ring length L, the game with moves (a(L−2) + c)·B + δ runs F on a ring of L cells, one initial configuration after another.

This is formally verified (SubGame.Univ.universal), as is the Turing-machine version: every deterministic Turing machine with a bounded tape is simulated on all inputs (SubGame.TM.tm_universal).

Theorem 3: complexity

Deciding whether n, written in binary, is a P-position is:

  • PSPACE-complete even for a bounded number of moves written in unary, and in fact for one explicit one-parameter family SL.
  • EXPTIME-complete for a bounded number of moves written in binary. So no polynomial-time algorithm exists, unconditionally.

Open problem

Is there a number of moves n with 3 ≤ n ≤ 25 for which periods are not polynomially bounded? For n ≤ 2 periods are at most 2 max S, and for every n ≥ 26 the answer is yes. The question is stated formally in Lean as SubGame.OpenGap.

How the construction works

The outcome bit of a position satisfies w(n) = NOR(w(n−s) : s ∈ S), so the game is a shift register with NOR feedback. Split the positions into blocks of length B = 260. Each residue within a block is one of three kinds:

  • a clock, which is always a P-position,
  • a zero residue, which is always an N-position, or
  • a wire, which carries one logic bit per block.

With a carefully found layout, every wire computes a NOR gate of prescribed inputs, and one long move gives a delay line of k blocks. Because NOR is universal, the game can run a circuit. For Theorem 1 that circuit is a bit-serial binary counter, and for Theorem 2 it is a fixed circuit that enumerates inputs and runs a cellular automaton.

Reducing the number of moves

1061 → 169 → 67 → 56 → 54 → 48 → 38 → 29 → 26

The early drops came from Sidon layouts, greedy set cover and simulated annealing. The next steps came from exact CP-SAT optimization of the clocks and covering moves, followed by large-neighbourhood search over wire positions. The last step came from also shortening the block from 377 to 260. Every design was checked by an exact verifier and by simulating the game itself.

Formally verified in Lean 4

The main theorems are formalized in Lean 4 with Mathlib. The headline statement, main_exact, gives exactly 26 moves, max S = 260k − 16 and period (max S + 16) · 2(max S + 16)/260. The explicit counterexample for k = 6719 is guy_explicit, and guy_false_of_ge shows Guy's bound fails for every n ≥ 26.
